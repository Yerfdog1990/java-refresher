# Bulk Operations on Lists 

## 1. Overview

This lesson covers working with **multiple elements at once** in a list. Instead of handling items one by one, bulk operations affect groups of elements efficiently and concisely — making list manipulation more expressive and often more performant, especially with larger collections.

- Start module: [bulk-operations-on-lists-start](https://github.com/Baeldung/learn-java-collections/tree/module2/bulk-operations-on-lists-start)
- Fully implemented reference: [bulk-operations-on-lists-end](https://github.com/Baeldung/learn-java-collections/tree/module2/bulk-operations-on-lists-end)

---

## 2. Why Use Bulk Operations?

Adding ten tasks with ten `add()` calls, or removing several completed items one at a time, is repetitive and clutters code. Bulk operations perform these actions on an entire collection in a **single, expressive method call**.

### 2.1. Performance and Convenience

Methods like `addAll()` can be more efficient than calling `add()` repeatedly in a loop, because implementations often optimize the process — e.g. an `ArrayList` may resize its internal array **once** rather than several times. More importantly, a single `addAll()` is far easier to read than an explicit loop.

### 2.2. Simplifying Common Tasks

Bulk operations shine for common scenarios:

- **Merging lists** — combining two lists into one.
- **List difference** — removing from one list all elements found in another.
- **Data initialization** — populating a list with predefined items.
- **Cleanup** — removing all items that meet certain criteria.

The payoff: less boilerplate, fewer off-by-one loop errors, and clearer intent. The examples below show the manual looping approach first, then the bulk equivalent.

## 3. Adding Multiple Elements with `addAll()`

### 3.1. Adding at the End

Manual approach — loop and add one by one:

```java
@Test
public void whenAddingAllElementsAtEnd_thenListContainsThem() {
    List<String> tasks = new ArrayList<>();
    tasks.add("Task A");

    List<String> newTasks = List.of("Task B", "Task C", "Task D");

    for (int i = 0; i < newTasks.size(); i++) {
        tasks.add(newTasks.get(i));
    }

    // assertions
}
```

Bulk equivalent — `addAll()` appends all elements of another collection:

```java
List<String> newTasks = List.of("Task B", "Task C", "Task D");
tasks.addAll(newTasks);
```

### 3.2. Adding at a Specific Index

Manual approach — repeated `add(index, element)` with careful index bookkeeping:

```java
@Test
public void whenAddingAllElementsAtIndex_thenListContainsThem() {
    List<String> tasks = new ArrayList<>(List.of("Task A", "Task E"));
    List<String> itemsToInsert = List.of("Task B", "Task C", "Task D");
    int insertionIndex = 1;

    for (int i = 0; i < itemsToInsert.size(); i++) {
        tasks.add(insertionIndex + i, itemsToInsert.get(i));
    }

    // assertions
}
```

Bulk equivalent — the overloaded `addAll(int index, Collection)`:

```java
List<String> tasks = new ArrayList<>(List.of("Task A", "Task E"));
List<String> itemsToInsert = List.of("Task B", "Task C", "Task D");
tasks.addAll(1, itemsToInsert);
```

Existing items at or after the position are shifted to make room — much cleaner than manual index manipulation.

## 4. Removing Groups of Elements

### 4.1. Removing Multiple Elements

Manual approach — nested loop removing every occurrence:

```java
@Test
public void whenExhaustivelyRemoving_thenListNotContainingAny() {
    List<String> tasks = new ArrayList<>(List.of("Task A", "Task B", "Task C", "Task B"));
    List<String> toRemove = List.of("Task B", "Task D");

    for (int i = 0; i < toRemove.size(); i++) {
        String elementToRemove = toRemove.get(i);
        while (tasks.contains(elementToRemove)) {
            tasks.remove(elementToRemove);
        }
    }

    // assertions
}
```

Bulk equivalent — `removeAll()` removes **every** occurrence of every element in the given collection:

```java
List<String> tasks = new ArrayList<>(List.of("Task A", "Task B", "Task C", "Task B"));
List<String> toRemove = List.of("Task B", "Task D");

tasks.removeAll(toRemove);
```

> Related: `retainAll(c)` does the opposite — keeps only elements also present in `c`, removing the rest.

### 4.2. Removing Elements Conditionally

Manual approach — must iterate in **reverse**, because removing an item shifts remaining elements left and a forward loop would skip items:

```java
@Test
public void whenRemovingElementsConditionally_thenListNotContainingAny() {
    List<String> tasks = new ArrayList<>(List.of("Task Important", "Task Minor", "Task Urgent", "Task Normal"));

    for (int i = tasks.size() - 1; i >= 0; i--) {
        String task = tasks.get(i);
        if (task.contains("Minor") || task.contains("Normal")) {
            tasks.remove(i);
        }
    }

    // assertions
}
```

Bulk equivalent — `removeIf()` takes a **`Predicate`** lambda and handles the traversal safely:

```java
List<String> tasks = new ArrayList<>(List.of("Task Important", "Task Minor", "Task Urgent", "Task Normal"));
tasks.removeIf(task -> task.contains("Minor") || task.contains("Normal"));
```

### 4.3. Clearing the Entire List

Often you can just **reassign** the variable (`tasks = new ArrayList<>()`) — expressive and performant. But reassignment isn't possible when the variable is `final` or when external references to the original list exist.

Manual in-place approach:

```java
@Test
public void whenClearingAList_thenListIsEmpty() {
    List<String> tasks = new ArrayList<>(List.of("Task A", "Task B", "Task C"));
    while (!tasks.isEmpty()) {
        tasks.remove(0);
    }

    // assertions
}
```

> `isEmpty()` (from `Collection`) returns `true` when the list has no elements — more readable than `size() == 0`.

Bulk equivalent — `clear()` empties the list in place, the most straightforward and efficient option:

```java
List<String> tasks = new ArrayList<>(List.of("Task A", "Task B"));
tasks.clear();
```

## 5. Replacing Elements with `replaceAll()`

To transform **every** element (rather than add/remove), the manual approach loops by index and uses `set()`:

```java
@Test
public void whenReplacingAllElements_thenAllElementsTransformed() {
    List<String> tasks = new ArrayList<>(List.of("Task A", "Task B", "Task C"));

    for (int i = 0; i < tasks.size(); i++) {
        String originalTask = tasks.get(i);
        tasks.set(i, originalTask + " - Done");
    }

    // assertions
}
```

Bulk equivalent — `replaceAll()` takes a **`UnaryOperator`** lambda and updates every element in place, no new list or index management:

```java
List<String> tasks = new ArrayList<>(List.of("Task A", "Task B", "Task C"));
tasks.replaceAll(task -> task + " - Done");
```

## 6. Quick Reference

| Goal | Bulk method | Argument | Notes |
|---|---|---|---|
| Append a collection | `addAll(c)` | `Collection` | Adds to the end |
| Insert a collection at index | `addAll(i, c)` | `int, Collection` | Shifts existing items |
| Remove matching elements | `removeAll(c)` | `Collection` | Removes all occurrences |
| Keep only matching elements | `retainAll(c)` | `Collection` | Removes everything else |
| Remove by condition | `removeIf(pred)` | `Predicate` | Safe traversal |
| Empty the list | `clear()` | — | In place |
| Transform every element | `replaceAll(op)` | `UnaryOperator` | In place |
| Check empty | `isEmpty()` | — | Cleaner than `size() == 0` |

**Functional interfaces used:** `removeIf` → `Predicate<E>` (returns `boolean`); `replaceAll` → `UnaryOperator<E>` (maps element → element).

---

## 7. Conclusion

Bulk operations simplify tasks that otherwise need manual loops and careful index management. We covered `addAll()` for appending and inserting groups, `removeAll()` and `removeIf()` for removing by collection or condition, `clear()` for emptying a list in place, and `replaceAll()` for transforming every element with a lambda. Together they make list code more concise, readable, and less error-prone.

## 8. List CRUD Operations (Deep Dive)

The **`List`** interface is an ordered collection that allows **duplicate elements** and provides **index-based access**. The most common implementation is `ArrayList`. Just like with `Deque`, we can group operations into **CRUD (Create, Read, Update, Delete)**.

### 8.1. Create (Insert)

| Method | Description |
|---|---|
| `add(E e)` | Adds an element to the end of the list |
| `add(int index, E e)` | Inserts an element at a specific index |
| `addAll(Collection c)` | Adds all elements from another collection |
| `addAll(int index, Collection c)` | Inserts a collection starting at a given index |

```java
import java.util.ArrayList;
import java.util.List;

public class CreateExample {
    public static void main(String[] args) {
        List<String> fruits = new ArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Orange");
        // Insert at index 1
        fruits.add(1, "Mango");
        System.out.println(fruits);
    }
}
```

**Output**

```
[Apple, Mango, Banana, Orange]
```

### 8.2. Read (Retrieve)

These methods retrieve information without modifying the list.

| Method | Description |
|---|---|
| `get(int index)` | Returns the element at the specified index |
| `contains(Object o)` | Checks whether an element exists |
| `indexOf(Object o)` | Returns the first index of an element |
| `lastIndexOf(Object o)` | Returns the last index of an element |
| `size()` | Returns the number of elements |
| `isEmpty()` | Checks whether the list is empty |

```java
import java.util.ArrayList;
import java.util.List;

public class ReadExample {
    public static void main(String[] args) {
        List<String> fruits = new ArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Orange");

        System.out.println("First Fruit: " + fruits.get(0));
        System.out.println("Contains Banana? " + fruits.contains("Banana"));
        System.out.println("Index of Orange: " + fruits.indexOf("Orange"));
        System.out.println("Size: " + fruits.size());
    }
}
```

**Output**

```
First Fruit: Apple
Contains Banana? true
Index of Orange: 2
Size: 3
```

### 8.3. Update (Modify)

The `set()` method replaces an existing element at a specified index.

| Method | Description |
|---|---|
| `set(int index, E element)` | Replaces the element at the specified index |

```java
import java.util.ArrayList;
import java.util.List;

public class UpdateExample {
    public static void main(String[] args) {
        List<String> fruits = new ArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Orange");
        // Replace Banana with Mango
        fruits.set(1, "Mango");
        System.out.println(fruits);
    }
}
```

**Output**

```
[Apple, Mango, Orange]
```

Unlike `Deque`, `List` provides a **direct update method** (`set()`).

### 8.4. Delete (Remove)

| Method | Description |
|---|---|
| `remove(int index)` | Removes the element at the specified index |
| `remove(Object o)` | Removes the first occurrence of an element |
| `removeAll(Collection c)` | Removes all matching elements |
| `clear()` | Removes all elements |

```java
import java.util.ArrayList;
import java.util.List;

public class DeleteExample {
    public static void main(String[] args) {
        List<String> fruits = new ArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Orange");
        // Remove Banana
        fruits.remove("Banana");
        // Remove Apple using index
        fruits.remove(0);
        System.out.println(fruits);
    }
}
```

**Output**

```
[Orange]
```

### 8.5. Complete CRUD Example

```java
import java.util.ArrayList;
import java.util.List;

public class ListCRUD {
    public static void main(String[] args) {
        List<String> students = new ArrayList<>();

        // CREATE
        students.add("Alice");
        students.add("Bob");
        students.add("Charles");
        System.out.println("After Create: " + students);

        // READ
        System.out.println("First Student: " + students.get(0));
        System.out.println("Contains Bob? " + students.contains("Bob"));
        System.out.println("List Size: " + students.size());

        // UPDATE
        students.set(1, "Brian");
        System.out.println("After Update: " + students);

        // DELETE
        students.remove("Charles");
        students.remove(0);
        System.out.println("After Delete: " + students);
    }
}
```

**Output**

```
After Create: [Alice, Bob, Charles]
First Student: Alice
Contains Bob? true
List Size: 3
After Update: [Alice, Brian, Charles]
After Delete: [Brian]
```

### 8.6. `List` vs `Deque` CRUD Comparison

| CRUD Operation | `List` | `Deque` |
|---|---|---|
| **Create** | `add()`, `add(index, e)` | `addFirst()`, `addLast()`, `offerFirst()`, `offerLast()` |
| **Read** | `get()`, `contains()`, `size()` | `peekFirst()`, `peekLast()`, `getFirst()`, `getLast()` |
| **Update** | `set(index, e)` | No direct update; remove and insert |
| **Delete** | `remove(index)`, `remove(object)`, `clear()` | `removeFirst()`, `removeLast()`, `pollFirst()`, `pollLast()`, `clear()` |

**Key difference:** A `List` supports **random access** (access or update elements by index), while a `Deque` is optimized for **efficient insertion and removal at both ends** and does not support direct indexed access.
