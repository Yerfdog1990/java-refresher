## 2. The List Interface

The `List` interface represents an **ordered collection** of elements. Each element's position is identified by a **zero-based integer index**: the first element is at position `0`, the second at `1`, and so on. We have full control over where each element is inserted and can operate on elements by position — making `List` well-suited to situations where insertion order and index-based access matter.

Within the framework, `List` extends **`SequencedCollection`** and **`Collection`** (and therefore `Iterable`) in that order:

```
Iterable → Collection → SequencedCollection → List
```

`SequencedCollection` allows operating at **both ends** of the list and **reversing** it. The `List` interface mainly defines the **index-based** methods, which `ArrayList` implements according to its needs.

Key characteristics of a `List`:

- **Order preservation** — element order is kept as we define it.
- **Index-based operations** — insert, retrieve, and remove elements by integer index.
- **Duplicates allowed** — unlike sets, a list permits duplicate elements.
- **A special iterator** — traverse in either direction (bidirectional) and modify during iteration.

Because `List` is an interface, it doesn't specify *how* data is stored — that's up to implementations such as `ArrayList` or `LinkedList`.

## 3. Basics of ArrayList

`ArrayList` implements the `List` interface and is named for storing the list internally as an **array**. It's a **resizable** array implementation: capacity grows automatically as elements are added. An `ArrayList` starts with a certain capacity, which can be set explicitly at initialization.

Benefits over a fixed-size array:

- **Fast random access** — implements the `RandomAccess` interface for constant-time, O(1), access by index.
- **Efficient iteration** — supports fail-fast iterators and bidirectional list iterators.
- **Automatic resizing** — grows as elements are added; also provides methods to ensure a minimum capacity and to trim capacity down to the current size.

Important caveats:

- **Not thread-safe by default.** Thread safety means multiple threads can access the same resource without erroneous or unpredictable behavior — `ArrayList` does not guarantee this.
- **Insertion/removal in the middle shifts elements.** Inserting or removing at an arbitrary interior position incurs the overhead of shifting subsequent elements. Adding or removing at the **end** does not shift anything.
- **Growth requires a copy.** When the internal array fills up, `ArrayList` allocates a larger array and copies everything over. These steps are rare, so the **amortized** time per add remains constant and very fast.

## 4. Initializing an ArrayList and the `size()` Method

Create an `ArrayList` and verify its size is `0`:

```java
@Test
void givenArrayList_whenUsingSizeMethod_thenArrayListSizeReturned() {
    List<String> tasks = new ArrayList<>();
    assertEquals(0, tasks.size());
}
```

We declare the `List` variable with a **type parameter** (`String` here) to specify the element type. The `size()` method, inherited from `Collection`, returns the **actual number of elements** in the list (not its capacity).

## 5. ArrayList Constructors

`ArrayList` provides three constructors: a **default** constructor, one that takes an **initial capacity**, and one that takes an **existing collection**. The starting capacity depends on which is used.

### 5.1. Default Constructor

Use `ArrayList()` when the element count isn't known upfront. The default capacity is set to **10** at initialization, and the list is created empty (as confirmed in section 4).

### 5.2. Specifying an Initial Capacity

When the approximate or exact size is known, use `ArrayList(int initialCapacity)` to reserve memory up front:

```java
@Test
void givenArrayListConstructorForInitialCapacity_whenInitializing_thenEmptyListCreated() {
    List<String> tasks = new ArrayList<>(5);
    assertEquals(0, tasks.size());
}
```

Providing an initial capacity **minimizes the number of times the list has to grow**, helping performance. It does **not** limit the final size — the list still expands as needed.

### 5.3. Using an Existing Collection

Initialize from another collection with `ArrayList(Collection<? extends E> c)`:

```java
@Test
void givenArrayListConstructorForExistingCollection_whenInitializing_thenEmptyListCreated() {
    List<String> subtasks = new ArrayList<>(20);
    List<String> tasks = new ArrayList<>(subtasks);
    assertEquals(0, tasks.size());
}
```

This creates a list containing all elements of the specified collection, **preserving their original order**. (Here `subtasks` is empty, so `tasks` is empty too.)

## 6. Creating an ArrayList Using Utility Methods

Sometimes we already have the elements in mind and want to build a list quickly.

### 6.1. Using `Arrays.asList()`

Builds a **fixed-size** list backed by the original array. It **allows `null`** values. Because it's backed by the array, changes to the array affect the list and vice versa. We can modify existing elements, but **adding or removing throws an exception**. To get a fully modifiable list, wrap it in a new `ArrayList`:

```java
@Test
void givenArraysAsList_whenWrappedInArrayList_thenNoExceptionThrown() {
    assertDoesNotThrow(() -> {
        List<String> days = Arrays.asList("Monday", "Tuesday", null);
        List<String> modifiableDays = new ArrayList<>(days);
        assertEquals(3, modifiableDays.size());
    });
}
```

`modifiableDays` is now a fully functioning `ArrayList` ready for insertion/removal.

### 6.2. Using `List.of()`

Builds an **unmodifiable, fixed-size** list — its size and elements cannot change. Wrap in a new `ArrayList` if a modifiable list is needed:

```java
@Test
void givenListOf_whenWrappedInArrayList_thenNoExceptionThrown() {
    List<Integer> numbers = List.of(1, 2, 3);
    assertDoesNotThrow(() -> {
        List<Integer> modifiableNumbers = new ArrayList<>(numbers);
        assertEquals(3, modifiableNumbers.size());
    });
}
```

Unlike `Arrays.asList()`, `List.of()` **does not allow `null`** — a null element throws a `NullPointerException`:

```java
@Test
void givenListOf_whenUsingNullElement_thenExceptionThrown() {
    assertThrows(NullPointerException.class, () -> {
        List<String> days = List.of("Monday", "Tuesday", null);
    });
}
```

## 7. Quick Reference

**Constructors**

| Constructor | Behavior |
|---|---|
| `new ArrayList<>()` | Empty list; default capacity 10 |
| `new ArrayList<>(int capacity)` | Empty list; reserves memory; doesn't cap final size |
| `new ArrayList<>(Collection c)` | Copies all elements, preserving order |

**Creation utilities**

| Method | Mutability | Nulls? | Notes |
|---|---|---|---|
| `Arrays.asList(...)` | Fixed-size (can set, can't add/remove) | Allowed | Backed by the array; changes propagate both ways |
| `List.of(...)` | Unmodifiable | **Not allowed** (`NullPointerException`) | Wrap in `new ArrayList<>(...)` for a modifiable copy |

**ArrayList traits:** fast random access (O(1)), amortized-constant add at end, interior insert/remove shifts elements, not thread-safe.

We explored the `List` interface and its role in the Collections Framework, then looked at `ArrayList` and what makes it practical for dynamic collections — resizable storage, fast random access, and amortized-constant appends, with the trade-offs of element shifting and no thread safety.
