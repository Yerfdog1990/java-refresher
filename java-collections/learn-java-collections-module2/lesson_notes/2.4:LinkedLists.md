## 2. What Is a LinkedList?

`LinkedList` represents a **sequential structure of nodes**, where each node stores data plus references to the **next** and **previous** nodes. Like `ArrayList`, it maintains elements in insertion order — but via a **chain of nodes** rather than a dynamically resized array.

`LinkedList` implements both **`List`** and **`Deque`** (double-ended queue). As a `Deque`, its doubly linked structure supports efficient insertion and removal at **both ends**, so it can act as a traditional **queue (FIFO)**, a **stack (LIFO)**, or a general-purpose deque.

In recent Java versions, both `List` and `Deque` extend **`SequencedCollection`**, which guarantees a consistent encounter order. `SequencedCollection` extends `Collection` (and therefore `Iterable`); `Deque` also extends `Queue`:

```
Iterable → Collection → SequencedCollection ─┬─→ List  ─┐
                                             └─→ Deque ─┴─→ LinkedList
                                                  ↑
                                                Queue
```

### Internal structure

Internally, `LinkedList` uses a **doubly linked list**. Each element lives in a private inner `Node` class with three fields:

- **`data`** — the actual element,
- **`next`** — reference to the following node,
- **`previous`** — reference to the preceding node.

The list keeps references to the **first (head)** and **last (tail)** nodes. All node-handling logic is transparent to the user, who interacts through the standard interfaces.

```
head                                          tail
 │                                             │
 ▼                                             ▼
[prev|A|next] ⇄ [prev|B|next] ⇄ [prev|C|next]
```

Because insertion/removal only updates references between adjacent nodes — **no element shifting** as in an array-based structure — these operations are efficient at any position (once the node is located).

## 3. Basic Operations on a LinkedList

### 3.1. Using `List` Methods

Standard CRUD works exactly as with `ArrayList`; internally it just rearranges node references:

```java
@Test
void givenLinkedList_whenUsingBasicListOperations_thenBehavesLikeArrayList() {
    List<String> fruitBasket = new LinkedList<>();
    fruitBasket.add("Apple");
    fruitBasket.add(0, "Banana");
    assertEquals("Banana", fruitBasket.get(0));
    assertEquals(2, fruitBasket.size());
}
```

These operations behave identically to `ArrayList` — the difference is in **performance characteristics** (section 4).

### 3.2. Using `Deque` Methods

Most of the same operations are available via `Deque` (except a direct update method):

```java
@Test
void givenLinkedList_whenUsingAsDeque_thenSupportsDoubleEndedOperations() {
    Deque<String> tasks = new LinkedList<>();
    tasks.offer("High Priority Task");
    tasks.offerFirst("Urgent Task");
    tasks.offerLast("Low Priority Task");
    assertEquals("Urgent Task", tasks.peekFirst());
    assertEquals("Low Priority Task", tasks.peekLast());
    assertEquals("Urgent Task", tasks.pollFirst());
    assertEquals("Low Priority Task", tasks.pollLast());
}
```

`peekFirst()`/`peekLast()` and `pollFirst()`/`pollLast()` roughly correspond to `List`'s `get()` and `remove()`, except they **return `null` on an empty list instead of throwing**.

### 3.3. Using Deque as a Stack (LIFO)

Example — browser back-button history:

```java
@Test
void givenLinkedList_whenUsingAsStack_thenSupportsLIFOOperations() {
    Deque<String> browserHistory = new LinkedList<>();
    browserHistory.push("google.com");
    browserHistory.push("stackoverflow.com");
    browserHistory.push("baeldung.com");
    assertEquals("baeldung.com", browserHistory.peek());
    assertEquals("baeldung.com", browserHistory.pop());
    assertEquals("stackoverflow.com", browserHistory.pop());
}
```

`push()` is equivalent to `addFirst()`; `pop()` is equivalent to `removeFirst()`.

### 3.4. Using Deque as a Queue (FIFO)

Example — print queue:

```java
@Test
void givenLinkedList_whenUsingAsQueue_thenSupportsFIFOOperations() {
    Deque<String> printQueue = new LinkedList<>();
    printQueue.offer("Document1.pdf");
    printQueue.offer("Document2.pdf");
    printQueue.offer("Document3.pdf");
    assertEquals("Document1.pdf", printQueue.poll());
    assertEquals("Document2.pdf", printQueue.peek());
}
```

`peek()` and `poll()` also **return `null` on an empty queue instead of throwing**.

> **Method families:** `offer`/`peek`/`poll` are the *non-throwing* forms (return `false`/`null`); `add`/`getFirst`/`removeFirst` are the *throwing* forms.

## 4. Comparing LinkedList and ArrayList

Both implement `List`, but their underlying structures make them behave differently.

| Aspect | LinkedList | ArrayList |
|---|---|---|
| **Data structure** | Doubly linked list | Resizable array |
| **Accessing elements** | Slower — traversal from head/tail | Fast — direct index access |
| **Insertion/deletion** | Fast — adjust node pointers | Slower — shifts elements |
| **Search** | O(n) linear | O(n) linear |
| **Memory allocation** | Non-contiguous (linked via pointers) | Contiguous block |
| **Memory overhead** | Higher (pointers per node) | Lower |
| **Memory usage** | Allocates only for stored elements | May over-allocate unused capacity |
| **Capacity** | Grows without pre-allocation | Has internal capacity; resizes when full |
| **Thread safety** | Not thread-safe; use `Collections.synchronizedList()` or `ConcurrentLinkedDeque` | Not thread-safe; use `Collections.synchronizedList()` or `CopyOnWriteArrayList` |
| **Use cases** | Frequent insertions/deletions, minimal random access | Frequent access, infrequent insert/remove |
| **Real-world examples** | Browser history (back/forward), undo/redo, LRU cache | Managing dynamic feeds — posts, likes, comments (e.g. Twitter, Instagram) |

> **Note on access:** although pointer adjustment for insert/remove is O(1), *reaching* an arbitrary interior position still requires O(n) traversal. `LinkedList` wins most clearly at the **ends** and when you already hold an iterator at the target position.

---

## 5. When LinkedList Is a Good Choice

Consider `LinkedList` when:

- You add or remove elements often **in the middle** of the sequence.
- You want to exploit **`Deque` operations** at the beginning or end.
- You want to avoid performance degradation from **large shifts** in an array-based structure.

If you mostly retrieve elements **by index** or do many **random reads**, `ArrayList` typically performs better.

---

## 6. Conclusion

`LinkedList` is an alternative `List` implementation built on a **doubly linked node structure** that implements both `List` and `Deque`, giving it the flexibility to act as a list, stack, or queue. Comparing it to `ArrayList` across performance, memory, and use cases, the key takeaway is: **`LinkedList` excels at frequent insertions and removals**, while **`ArrayList` is better for index-based access and random reads**.

## 7. Deque CRUD Operations (Deep Dive)

A **`Deque` (Double-Ended Queue)** is a linear data structure that allows insertion and deletion at **both the front and the rear**. In Java, the `Deque` interface is implemented by classes such as **`ArrayDeque`** and **`LinkedList`**.

Although "CRUD" (Create, Read, Update, Delete) is commonly used for databases, we can map it onto the operations available in a `Deque`.

### 7.1. Create (Insert)

| Method | Description | Throws Exception? |
|---|---|---|
| `addFirst(E e)` | Inserts at the front | Yes |
| `addLast(E e)` | Inserts at the rear | Yes |
| `offerFirst(E e)` | Inserts at the front | No (`false` if it fails) |
| `offerLast(E e)` | Inserts at the rear | No (`false` if it fails) |
| `push(E e)` | Pushes onto the front (stack behavior) | Yes |

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class CreateExample {
    public static void main(String[] args) {
        Deque<Integer> deque = new ArrayDeque<>();
        deque.addFirst(20);
        deque.addLast(30);
        deque.offerFirst(10);
        deque.offerLast(40);
        System.out.println(deque);
    }
}
```

**Output**

```
[10, 20, 30, 40]
```

### 7.2. Read (Access)

These methods retrieve elements **without removing** them.

| Method | Description |
|---|---|
| `getFirst()` | Returns the first element |
| `getLast()` | Returns the last element |
| `peekFirst()` | Returns first element or `null` |
| `peekLast()` | Returns last element or `null` |
| `peek()` | Same as `peekFirst()` |

```java
Deque<String> deque = new ArrayDeque<>();
deque.add("Apple");
deque.add("Banana");
deque.add("Orange");

System.out.println("First: " + deque.getFirst());
System.out.println("Last : " + deque.getLast());
System.out.println(deque);
```

**Output**

```
First: Apple
Last : Orange
[Apple, Banana, Orange]
```

The deque remains unchanged after reading.

### 7.3. Update (Modify)

A deque has **no direct update method** — it's designed primarily for insertion and removal at the ends. To update an element, you typically:

1. Remove it.
2. Insert the new value.

```java
Deque<String> deque = new ArrayDeque<>();
deque.add("Java");
deque.add("Python");
deque.add("C++");

deque.removeFirst();
deque.addFirst("Java 21");
System.out.println(deque);
```

**Output**

```
[Java 21, Python, C++]
```

For frequent updates at arbitrary positions, a `List` (such as `ArrayList` or `LinkedList`) is usually a better choice than a `Deque`.

### 7.4. Delete (Remove)

| Method | Description |
|---|---|
| `removeFirst()` | Removes the first element |
| `removeLast()` | Removes the last element |
| `pollFirst()` | Removes first element or returns `null` |
| `pollLast()` | Removes last element or returns `null` |
| `pop()` | Removes the first element (stack behavior) |

```java
Deque<Integer> deque = new ArrayDeque<>();
deque.add(10);
deque.add(20);
deque.add(30);
deque.add(40);

deque.removeFirst();
deque.removeLast();
System.out.println(deque);
```

**Output**

```
[20, 30]
```

### 7.5. Complete CRUD Example

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class DequeCRUD {
    public static void main(String[] args) {
        Deque<Integer> deque = new ArrayDeque<>();

        // CREATE
        deque.addFirst(20);
        deque.addFirst(10);
        deque.addLast(30);
        deque.addLast(40);
        System.out.println("After Create: " + deque);

        // READ
        System.out.println("First Element: " + deque.peekFirst());
        System.out.println("Last Element : " + deque.peekLast());

        // UPDATE
        deque.removeFirst();
        deque.addFirst(100);
        System.out.println("After Update: " + deque);

        // DELETE
        deque.removeLast();
        System.out.println("After Delete: " + deque);
    }
}
```

**Output**

```
After Create: [10, 20, 30, 40]
First Element: 10
Last Element : 40
After Update: [100, 20, 30, 40]
After Delete: [100, 20, 30]
```

### 7.6. Summary of Common `Deque` Methods

| CRUD Operation | Methods |
|---|---|
| **Create (Insert)** | `addFirst()`, `addLast()`, `offerFirst()`, `offerLast()`, `push()` |
| **Read (Access)** | `getFirst()`, `getLast()`, `peekFirst()`, `peekLast()`, `peek()` |
| **Update (Modify)** | No direct update method; remove and reinsert |
| **Delete (Remove)** | `removeFirst()`, `removeLast()`, `pollFirst()`, `pollLast()`, `pop()` |

**Key distinction:** methods beginning with **`add`**, **`remove`**, and **`get`** *throw an exception* if the operation can't be completed (e.g. removing from an empty deque), while **`offer`**, **`poll`**, and **`peek`** *return a special value* (`false` or `null`) instead. The latter set is safer when you're unsure whether the deque contains elements.
