## 2. Adding Elements

A base list is set up before each test with `@BeforeEach`:

```java
class JavaCollectionsTests {

    private List<String> myList;

    @BeforeEach
    void setUp() {
        myList = new ArrayList<>(List.of("A", "B", "C", "D", "E"));
    }
}
```

> **Program to the interface:** we declare the variable as `List<String>`, not `ArrayList<String>`. This focuses on **behavior** (the `List` interface) rather than the implementation, and lets us swap in another `List` implementation easily.

### 2.1. Appending Elements

`add(E e)` appends to the **end** of the list:

```java
@Test
void whenCallingAddOnAnArrayList_thenGetExpectedResult() {
    myList.add("F");
    myList.add("G");

    assertEquals(List.of("A", "B", "C", "D", "E", "F", "G"), myList);
}
```

### 2.2. Inserting at a Specific Position

`add(int index, E e)` inserts at an index, **shifting** existing elements to make room:

```java
@Test
void whenCallingAddWithIndexOnAnArrayList_thenGetExpectedResult() {
    myList.add(1, "B_0");

    assertEquals(List.of("A", "B_0", "B", "C", "D", "E"), myList);
}
```

`addFirst()` and `addLast()` conveniently prepend and append:

```java
@Test
void whenCallingAddFirstAndAddLastOnAnArrayList_thenGetExpectedResult() {
    myList.addFirst("A_0");
    assertEquals(List.of("A_0", "A", "B", "C", "D", "E"), myList);

    myList.addLast("F");
    assertEquals(List.of("A_0", "A", "B", "C", "D", "E", "F"), myList);
}
```

Under the hood, `addFirst(e)` delegates to `add(0, e)` and `addLast(e)` to `add(e)`. `addLast()` may seem redundant for a `List`, but both come from the **`SequencedCollection`** interface, which supports a broader range of collection types.

## 3. Retrieving Elements

### 3.1. Retrieving by Index

`get(int index)` reads the element at a position. An out-of-range index throws `IndexOutOfBoundsException`:

```java
@Test
void whenCallingGetOnAnArrayList_thenGetExpectedResult() {
    String firstElement = myList.get(0);
    assertEquals("A", firstElement);

    String theThirdElement = myList.get(2);
    assertEquals("C", theThirdElement);

    // when the given index is out of the range [0, size)
    assertThrows(IndexOutOfBoundsException.class, () -> myList.get(-5));
    assertThrows(IndexOutOfBoundsException.class, () -> myList.get(42));
}
```

### 3.2. Retrieving the First and Last Elements

`getFirst()` and `getLast()` read the ends:

```java
@Test
void whenCallingGetFirstAndGetLastOnAnArrayList_thenGetExpectedResult() {
    String firstElement = myList.getFirst();
    assertEquals("A", firstElement);

    String theThirdElement = myList.getLast();
    assertEquals("E", theThirdElement);
}
```

`getFirst()` is *almost* the same as `get(0)`, and `getLast()` *almost* the same as `get(size() - 1)` — the difference shows up on an **empty list**:

```java
@Test
void whenCallingGetGetFirstAndGetLastOnAnEmptyArrayList_thenGetExpectedExceptions() {
    List<String> emptyList = new ArrayList<>();

    // get()
    assertThrows(IndexOutOfBoundsException.class, () -> emptyList.get(0));

    // getFirst() and getLast()
    assertThrows(NoSuchElementException.class, () -> emptyList.getFirst());
    assertThrows(NoSuchElementException.class, () -> emptyList.getLast());
}
```

All three throw on an empty list, but with **different exceptions**: `get(0)` throws `IndexOutOfBoundsException`, while `getFirst()`/`getLast()` throw `NoSuchElementException`.

## 4. Checking for Containment

### 4.1. `contains()`

Returns a `boolean` — `true` if the element is present, else `false`:

```java
@Test
void whenCallingContainsOnAnArrayList_thenGetExpectedResult() {
    boolean containsB = myList.contains("B");
    assertTrue(containsB);

    boolean containsX = myList.contains("X");
    assertFalse(containsX);
}
```

### 4.2. `indexOf()`

Returns the `int` index of the **first occurrence**, or `-1` if not present:

```java
@Test
void whenCallingIndexOfOnAnArrayList_thenGetExpectedResult() {
    int indexOfB = myList.indexOf("B");
    assertEquals(1, indexOfB); // B exists at index 1

    int indexOfX = myList.indexOf("X");
    assertEquals(-1, indexOfX); // X doesn't exist
}
```

> Both methods rely on **`equals()`** to determine containment. To check by a *condition*, loop manually or use the **Streams API**.

## 5. Removing Elements

### 5.1. Removing by Element

`remove(Object o)` removes the **first occurrence** and returns a `boolean`. If the element isn't present, it returns `false` and leaves the list unchanged:

```java
@Test
void whenCallingRemoveByElementOnAnArrayList_thenGetExpectedResult() {
    boolean removeD = myList.remove("D");
    assertTrue(removeD);
    assertEquals(List.of("A", "B", "C", "E"), myList);

    // when removing a non-existing element
    boolean removeX = myList.remove("X");
    assertFalse(removeX);
    assertEquals(List.of("A", "B", "C", "E"), myList); // unchanged
}
```

With duplicates, each call removes only one occurrence:

```java
@Test
void whenCallingRemoveByElementOnAnArrayListWithDuplicateElements_thenGetExpectedResult() {
    myList.add("D"); // add another "D"
    assertEquals(List.of("A", "B", "C", "D", "E", "D"), myList);

    boolean removeD = myList.remove("D");
    assertTrue(removeD);
    assertEquals(List.of("A", "B", "C", "E", "D"), myList); // first "D" removed

    boolean removeD2 = myList.remove("D");
    assertTrue(removeD2);
    assertEquals(List.of("A", "B", "C", "E"), myList); // second "D" removed
}
```

### 5.2. Removing by Index

`remove(int index)` removes at a position, **returns the removed element**, and shifts subsequent items to fill the gap. Out-of-range index throws `IndexOutOfBoundsException`:

```java
@Test
void whenCallingRemoveByIndexOnAnArrayList_thenGetExpectedResult() {
    String removedB = myList.remove(1);
    assertEquals("B", removedB);
    assertEquals(List.of("A", "C", "D", "E"), myList);

    // when the given index is out of the range [0, size)
    assertThrows(IndexOutOfBoundsException.class, () -> myList.remove(42));
}
```

> **Overload gotcha:** `remove(int)` targets an **index**, while `remove(Object)` targets an **element**. For a `List<Integer>`, `remove(1)` removes index 1, not the value `1` — use `remove(Integer.valueOf(1))` for the value.

`removeFirst()` and `removeLast()` remove the ends (similar to `remove(0)` and `remove(size() - 1)`):

```java
@Test
void whenCallingRemoveFirstAndRemoveLastOnAnArrayList_thenGetExpectedResult() {
    String firstRemoved = myList.removeFirst();
    assertEquals("A", firstRemoved);
    assertEquals(List.of("B", "C", "D", "E"), myList);

    String lastRemoved = myList.removeLast();
    assertEquals("E", lastRemoved);
    assertEquals(List.of("B", "C", "D"), myList);
}
```

**Behavior on an empty list differs by method:**

```java
@Test
void whenCallingRemovingMethodsOnAnEmptyArrayList_thenGetExpectedExceptions() {
    List<String> emptyList = new ArrayList<>();

    // remove() by index
    assertThrows(IndexOutOfBoundsException.class, () -> emptyList.remove(0));

    // remove() by element
    boolean removeX = emptyList.remove("X");
    assertFalse(removeX);

    // removeFirst() and removeLast()
    assertThrows(NoSuchElementException.class, () -> emptyList.removeFirst());
    assertThrows(NoSuchElementException.class, () -> emptyList.removeLast());
}
```

| Method on empty list | Result |
|---|---|
| `remove(int index)` | Throws `IndexOutOfBoundsException` |
| `remove(Object o)` | Returns `false` (no exception) |
| `removeFirst()` / `removeLast()` | Throws `NoSuchElementException` |

## 6. Updating Elements in Place

`set(int index, E element)` replaces the value at an index **without changing the size**, and **returns the previous value**:

```java
@Test
void whenCallingSetOnAnArrayList_thenGetExpectedResult() {
    String previousAt1 = myList.set(1, "B_1");
    assertEquals("B", previousAt1);
    assertEquals(List.of("A", "B_1", "C", "D", "E"), myList);

    previousAt1 = myList.set(1, "B_2");
    assertEquals("B_1", previousAt1); // previous value was now B_1
    assertEquals(List.of("A", "B_2", "C", "D", "E"), myList);

    assertThrows(IndexOutOfBoundsException.class, () -> myList.set(42, "X"));
}
```

## 7. Displaying Elements

The simplest way is `toString()` (called implicitly by `println`):

```java
@Test
void whenPrintingArrayListByToString_thenGetExpectedResult() {
    System.out.println(myList);
}
```

Unlike raw arrays (which print an object reference), a Collection's `toString()` shows the elements:

```
[A, B, C, D, E]
```

For custom output, loop explicitly:

```java
@Test
void whenPrintingArrayListByLooping_thenGetExpectedResult() {
    for (int i = 0; i < myList.size(); i++) {
        System.out.printf("index %d: %s%n", i, myList.get(i));
    }
}
```

Output:

```
index 0: A
index 1: B
index 2: C
index 3: D
index 4: E
```

The loop is more flexible since we control the format.

## 8. Quick Reference

| Operation | Method | Returns | On empty / out of range |
|---|---|---|---|
| Append | `add(e)` | `boolean` | — |
| Insert at index | `add(i, e)` | `void` | `IndexOutOfBoundsException` |
| Prepend / append | `addFirst(e)` / `addLast(e)` | `void` | — |
| Get by index | `get(i)` | element | `IndexOutOfBoundsException` |
| Get ends | `getFirst()` / `getLast()` | element | `NoSuchElementException` |
| Contains | `contains(o)` | `boolean` | — |
| Find index | `indexOf(o)` | `int` (`-1` if absent) | — |
| Remove by element | `remove(o)` | `boolean` | returns `false` |
| Remove by index | `remove(i)` | removed element | `IndexOutOfBoundsException` |
| Remove ends | `removeFirst()` / `removeLast()` | removed element | `NoSuchElementException` |
| Update in place | `set(i, e)` | previous value | `IndexOutOfBoundsException` |
| Size | `size()` | `int` | — |

Containment and removal-by-element use **`equals()`**. `set()` and `get()` do **not** change size; `add`/`remove` do.

## 9. Conclusion

We explored the basic operations that form the backbone of working with `ArrayList` and the `List` interface: adding (`add`, `addFirst`, `addLast`), retrieving (`get`, `getFirst`, `getLast`), checking containment (`contains`, `indexOf`), removing (`remove` by element/index, `removeFirst`, `removeLast`), updating (`set`), and displaying (`toString`, looping). The goal is comfort applying these across different scenarios — including the subtle differences in exceptions and return values on empty lists and with the overloaded `remove`.
