# Basic HashMap Operations

Source: [Basic HashMap Operations – Baeldung](https://www.baeldung.com/members/courses/learn-java-collections/lessons/lesson-2-basic-hashmap-operations)

## 1. Overview

After initializing a `HashMap`, we can perform a variety of basic operations to manage its key-value pairs: adding, retrieving, updating, and removing entries, plus checking whether a key or value exists. All operations covered here are defined in the `Map` interface, so they apply to any `Map` implementation, not just `HashMap`.

## 2. Key and Value Presence Check Operations

- `containsKey(Object key)`: returns `true` if the map contains a mapping for the given key.
- `containsValue(Object value)`: returns `true` if one or more keys map to the given value.
- `isEmpty()`: returns `true` if the map contains no entries at all.

Useful for validating data presence before deciding whether to add or update a mapping.

Example, using `Map<String, Task> taskMap` (reset before each test):

```java
@Test
void givenHashMap_whenCheckingKeyValuePresence_thenKeyPresenceVerified() {
    assertFalse(taskMap.isEmpty());
    assertTrue(taskMap.containsKey(task1.getCode()));
    assertTrue(taskMap.containsValue(task1));
}
```

**Note**: for `containsKey()` and `containsValue()` to work correctly with custom types, those types must properly implement `equals()` and `hashCode()`.

## 3. Get Operations

### 3.1. get(Object key)

Returns the value mapped to the specified key.

```java
@Test
void givenHashMap_whenUsingGet_thenEntryReturned() {
    assertEquals(task1, taskMap.get("T001"));
}
```

Can return `null` either because there's no mapping for the key, or because the mapping exists but its value is `null`. Use `containsKey()` to distinguish the two cases.

### 3.2. getOrDefault(Object key, V defaultValue)

Returns the value mapped to the key, or `defaultValue` if there's no mapping for the key.

```java
@Test
void givenHashMap_whenUsingGetOrDefault_thenDefaultReturned() {
    assertEquals(task1, taskMap.getOrDefault("T999", task1));
}
```

Since `"T999"` isn't in `taskMap`, the default (`task1`) is returned. Use this instead of `get()` when a default is preferable to `null` for a missing key. With `getOrDefault()`, `null` is only returned when the mapping exists and its value is `null`.

## 4. Replace Operations

### 4.1. replace(K key, V value)

Replaces the entry for the specified key.

```java
@Test
void givenHashMap_whenUsingReplace_thenValueReplaced() {
    Task task1_replacement = new Task("T001", "Start Report", "Start quarterly sales report", LocalDate.of(2050, 7, 15));
    Task oldValue = taskMap.replace("T001", task1_replacement);
    assertTrue(task1_replacement == taskMap.get("T001"));
    assertTrue(oldValue == task1);

    // nothing happens and null return for non-existing key
    Task oldNonExistingValue = taskMap.replace("T999", task1_replacement);
    assertNull(oldNonExistingValue);
    assertFalse(taskMap.containsKey("T999"));
}
```

Returns the old value, and only updates the map if the key already exists.

### 4.2. replace(K key, V oldValue, V newValue) with Value Check

Updates a mapping only if the key is currently associated with a specific value — a conditional replacement.

```java
@Test
void givenHashMap_whenUsingReplaceConditionally_thenValueReplaced() {
    Task task1_replacement = new Task("T001", "Different name", "Different description", LocalDate.of(2050, 7, 15));

    boolean replaced1 = taskMap.replace("T001", task1, task1_replacement);

    assertEquals("Different name", taskMap.get("T001").getName());
    assertTrue(replaced1);
}
```

Returns a `boolean` indicating success. The value check relies on the value type's `equals()` implementation — replacement occurs only if the provided old value is considered equal to the current entry.

### 4.3. put(K key, V value)

Can also be used to replace an existing mapping.

```java
@Test
void givenHashMap_whenUsingPutForExistingKey_thenValueReplaced() {
    Task task1_replacement = new Task("T001", "Start Report", "Start quarterly sales report", LocalDate.of(2050, 7, 15));
    Task oldValue = taskMap.put("T001", task1_replacement);

    assertSame(task1_replacement, taskMap.get("T001"));
    assertSame(task1, oldValue);
}
```

When the key already exists, `put()` behaves like `replace()` — returns the old value and updates the entry.

## 5. Add Element Operations

### 5.1. put(K key, V value)

Adds a new mapping using the key and value arguments.

```java
@Test
void givenHashMap_whenUsingPut_thenEntryAdded() {
    Task newTask4 = new Task("T004", "New Task Name", "New Task Description", LocalDate.of(2050, 7, 15));

    taskMap.put(newTask4.getCode(), newTask4);

    assertEquals(4, taskMap.size());
    assertTrue(taskMap.containsKey("T004"));
    assertTrue(taskMap.containsValue(newTask4));
}
```

`put()` effectively works as a "replace-or-add" operation.

### 5.2. putIfAbsent(K key, V value)

Adds a mapping only if the key isn't already associated with a (non-null) value — unlike `put()`, it won't overwrite an existing mapping.

Key exists with a non-null value → no effect:

```java
@Test
void givenHashMap_whenUsingPutIfAbsent_thenEntryAddedIfAbsent() {
    Task newTask
      = new Task("TNEW", "Different Name", "Different Description", LocalDate.of(2050, 7, 15));

    Task oldTask1 = taskMap.putIfAbsent("T001", newTask);
    assertNotEquals("Different Name", taskMap.get("T001").getName());
    assertSame(task1, oldTask1);
}
```

Key doesn't exist → adds:

```java
assertFalse(taskMap.containsKey("T005"));
Task oldNonExistingTask5 = taskMap.putIfAbsent("T005", newTask);

assertEquals("Different Name", taskMap.get("T005").getName());
assertNull(oldNonExistingTask5);
```

Key exists but value is `null` → adds:

```java
taskMap.put("T006", null);
assertTrue(taskMap.containsKey("T006"));
Task oldNullTask6 = taskMap.putIfAbsent("T006", newTask);

assertEquals("Different Name", taskMap.get("T006").getName());
assertNull(oldNullTask6);
```

`putIfAbsent()` always returns the value already associated with the key, or `null` if no mapping existed.

## 6. Remove Operations

### 6.1. remove(Object key)

Removes the mapping for the specified key if present.

```java
@Test
void givenHashMap_whenUsingRemove_thenEntryRemoved() {
    Task removed = taskMap.remove("T001");
    assertSame(task1, removed);
    assertEquals(2, taskMap.size());
    assertFalse(taskMap.containsKey("T001"));
}
```

Returns the removed value.

### 6.2. remove(Object key, Object value)

Removes the entry for the specified key only if it's mapped to the given value.

```java
@Test
void givenHashMap_whenUsingRemoveConditionally_thenEntryRemovedConditionally() {
    taskMap.remove("T001", task1);
    assertEquals(2, taskMap.size());
    assertFalse(taskMap.containsKey("T001"));
    assertFalse(taskMap.containsValue(task1));

    taskMap.remove("T003", task2);
    assertEquals(2, taskMap.size());
    assertTrue(taskMap.containsKey("T003"));
    assertTrue(taskMap.containsValue(task3));
}
```

`"T001"` is removed because it's mapped to `task1`. `"T003"` is NOT removed because it's mapped to `task3`, not `task2`.

## 7. Bulk Operations

Bulk operations act on all or a subset of a map's entries efficiently, without manually iterating and applying an action to each entry.

### 7.1. putAll(Map m)

Copies all mappings from one map into another. Internally calls `put()` for each entry — existing mappings are left untouched unless keys overlap.

```java
@Test
void givenHashMap_whenUsingPutAll_thenAllEntriesAdded() {
    Map<String, Task> newTaskMap = new HashMap<>(Map.of(
        "T001", new Task("T001", "Different name", "Different description", null),
        "T007", new Task("T007", "Another task", "Another description", null)
        ));

    newTaskMap.putAll(taskMap);
    assertEquals(4, newTaskMap.size());
    assertNotEquals("Different name", newTaskMap.get("T001").getName());
}
```

### 7.2. replaceAll(BiFunction function)

Replaces all values in the map with new values based on a provided function, without manually iterating. The `BiFunction` receives the key as the first parameter and the value as the second, and must return a value of the map's value type.

```java
@Test
void givenHashMap_whenUsingReplaceAll_thenAllEntriesReplaced() {
    taskMap.replaceAll((code, task) -> {
        String newDescription = task.getDescription() + " - experimental task";
        task.setDescription(newDescription);
        return task;
    });

    assertTrue((task1.getDescription()).equals("Finish quarterly sales report - experimental task"));
}
```

### 7.3. clear()

Removes all mappings from the map, leaving it empty.

```java
@Test
void givenHashMap_whenUsingClear_thenAllEntriesRemoved() {
    taskMap.clear();
    assertEquals(0, taskMap.size());
}
```

## 8. Conclusion

Core `Map` operations covered: presence checks, retrieval, replacement, addition, removal, and bulk operations. Since these methods are defined on `Map` itself, the same patterns apply uniformly to `HashMap` and any other `Map` implementation.

Key takeaways: `put()` has a dual nature as a "replace-or-add" operation, and the conditional variants — `replace(K, V, V)`, `putIfAbsent()`, and `remove(Object, Object)` — all rely on the `equals()` contract of the key or value type. Keeping that contract in mind is essential for reasoning confidently about how a `Map` will behave.
