# Enhanced For-Loops: A Simple Iteration Technique 

## 1. Overview

This lesson focuses on a common, straightforward approach for iterating over collections: the **enhanced for-loop**, also known as the **for-each loop**.

- Start module: `enhanced-for-loops-start`
- Fully implemented reference: `enhanced-for-loops-end`

---

## 2. Traditional Index-Based Loop

The base `List` of `Task` objects used throughout the lesson:

```java
class JavaCollectionsTests {
    private List<Task> tasks;

    @BeforeEach
    void setUp() {
        tasks = new ArrayList<>(List.of(
          new Task("001", "Task A", "This is Task A", null),
          new Task("002", "Task B", "This is Task B", null),
          new Task("003", "Task C", "This is Task C", null),
          new Task("004", "Task D", "This is Task D", null)
        ));
    }
}
```

The traditional **index-based `for` loop** gives full control by working directly with the index:

```java
@Test
void whenUsingTraditionalForLoop_thenCorrect() {
    for (int i = 0; i < tasks.size(); i++) {
        System.out.println(tasks.get(i).getName());
    }
}
```

Output:

```
Task A
Task B
Task C
Task D
```

While effective, the index-based loop has drawbacks:

- **Manual index management** — tracking indices invites off-by-one errors.
- **Verbosity** — the code is longer and less readable.

The enhanced for-loop is a simpler alternative when the index isn't needed.

---

## 3. The Enhanced `for` Loop

Java's enhanced for-loop iterates over collections or arrays **without manually managing an index variable**.

Syntax:

```java
for (ElementType element : collectionOrArray) {
    // reference 'element' directly
}
```

It works with **arrays** and any collection type that implements the **`Iterable`** interface (such as `List`).

Same example, using the enhanced loop:

```java
@Test
void whenUsingEnhancedForLoop_thenCorrect() {
    for (Task task : tasks) {
        System.out.println(task.getName());
    }
}
```

The loop iterates through each element automatically — no explicit index — and produces the same output.

It works with arrays too:

```java
@Test
void whenUsingEnhancedForLoopOnAnArray_thenCorrect() {
    Task[] taskArray = tasks.toArray(new Task[0]);
    for (Task task : taskArray) {
        System.out.println(task.getName());
    }
}
```

The enhanced loop is shorter, more readable, and removes the need to manage index variables or worry about `size()`/`length`.

## 4. Limitations and Pitfalls

### 4.1. Needing Access to Indexes

When an element's **position** matters — e.g. comparing adjacent elements — a for-each loop falls short. The index-based loop is straightforward:

```java
@Test
void whenIndexIsRequiredInLoop_thenTraditionalForLoopIsSimple() {
    for (int i = 0; i < tasks.size(); i++) {
        System.out.printf("[ %s ]'s index is: %d. ", tasks.get(i).getName(), i);
        if (i > 0) {
            System.out.printf("Its previous task is [ %s ].\n", tasks.get(i - 1).getName());
        } else {
            System.out.println("It doesn't have a previous task.");
        }
    }
}
```

Output:

```
[ Task A ]'s index is: 0. It doesn't have a previous task.
[ Task B ]'s index is: 1. Its previous task is [ Task A ].
[ Task C ]'s index is: 2. Its previous task is [ Task B ].
[ Task D ]'s index is: 3. Its previous task is [ Task C ].
```

The enhanced loop must track the index manually with an extra variable:

```java
@Test
void whenIndexIsRequiredInLoop_thenEnhancedForLoopNeedsIndexVariable() {
    int i = 0;
    for (Task task : tasks) {
        System.out.printf("[ %s ]'s index is: %d. ", task.getName(), i);
        if (i > 0) {
            System.out.printf("Its previous task is [ %s ].\n", tasks.get(i - 1).getName());
        } else {
            System.out.println("It doesn't have a previous task.");
        }
        i++;
    }
}
```

For a `List` you could use `indexOf`, but the traditional loop stays clearer when index access is required.

### 4.2. Reverse Iteration

Enhanced for-loops only go **forward**. For reverse order, use the traditional approach:

```java
@Test
void whenReverseIteration_thenTraditionalForLoopWorks() {
    for (int i = tasks.size() - 1; i >= 0; i--) {
        System.out.println(tasks.get(i).getName());
    }
}
```

Output:

```
Task D
Task C
Task B
Task A
```

### 4.3. Modifying the List During Iteration

A traditional loop lets us add/remove elements during iteration while keeping the flow transparent:

```java
@Test
void whenListIsModifiedWhileIteration_thenTraditionalForLoopCorrect() {
    for (int i = 0; i < tasks.size(); i++) {
        Task task = tasks.get(i);
        if (i == 1) {
            tasks.add(2, new Task("42", "New Task X", "a new task", null));
        }
        if (task.getName().equals("Task C")) {
            tasks.removeLast();
        }
        System.out.println(task.getName());
    }
}
```

Output:

```
Task A
Task B
New Task X
Task C
```

However, adding or removing during an **enhanced** for-loop typically throws a **`ConcurrentModificationException`**:

```java
@Test
void whenListIsModifiedWhileIteration_thenEnhancedForLoopFails() {
    assertThrows(ConcurrentModificationException.class, () -> {
        for (Task task : tasks) {
            if (task.getName().equals("Task B")) {
                tasks.add(new Task("42", "New Task X", "a new task", null));
            }
            System.out.println(task);
        }
    });
}
```

> **Why:** the enhanced loop uses the collection's `Iterator` under the hood, which is **fail-fast** — it detects structural changes made outside the iterator and throws. To modify during iteration, use a traditional loop or an **`Iterator`** (with `iterator.remove()`), covered in a later lesson.

## 5. Conclusion

| Feature | Traditional For-Loop | Enhanced For-Loop |
|---|---|---|
| Syntax simplicity | More verbose | Cleaner, easier to read |
| Index control / access by index | Yes, built-in index variable | No — extra variable, manual tracking |
| Allows modification during iteration | Yes | No — `ConcurrentModificationException` |
| Supports reverse iteration | Yes | No — forward only |

The enhanced for-loop removes boilerplate, simplifies iteration logic, and improves readability, making it ideal for most use cases — but it has real limitations around index access, reverse order, and modification.

> **Autoboxing note:** with primitive arrays, enhanced loops may trigger autoboxing, potentially affecting performance — though this is usually a minimal concern in practice.

Understanding each approach's strengths and limitations helps us write cleaner, safer, and more effective code.
