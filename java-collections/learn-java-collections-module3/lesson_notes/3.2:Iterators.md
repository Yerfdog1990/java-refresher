# Iterators: Fine-Grained Control over Traversal 

## 1. Overview

Traditional and enhanced for-loops work well in many cases, but fall short for complex operations — removing elements during iteration, inserting mid-loop, or traversing in reverse. Enhanced for-loops don't support these, and traditional loops need cumbersome index management.

**Iterators** solve this. This lesson explores how **`Iterator`** and **`ListIterator`** give fine-grained control over traversing and modifying Java collections.

- Fully implemented reference: `iterators-end`

---

## 2. Understanding Iterators

An **iterator** is an object designed specifically for traversing a collection. It acts as a **cursor** walking through elements one by one, without exposing the underlying implementation. It provides a uniform, safe mechanism for iteration across collection types and allows **safe element removal** during iteration — something enhanced for-each loops can't do.

In Java, `Iterator` is an interface in the Collections Framework. Every collection that implements **`Iterable`** supports iterators — including `List`, `Set`, and other data structures.

---

## 3. Key Methods of `Iterator`

- **`hasNext()`** — checks if more elements remain.
- **`next()`** — returns the next element and advances the cursor.
- **`remove()`** — removes the element returned by the most recent `next()`.
- **`forEachRemaining()`** — iterates from the current position to the end.

### 3.1. Iterating With `hasNext()` and `next()`

```java
@Test
void whenIteratingWithIteratorHasNextAndNext_thenCorrect() {
    Iterator<Task> iterator = tasks.iterator();
    while (iterator.hasNext()) {
        Task task = iterator.next();
        System.out.println(task.getName());
    }
}
```

Output:

```
Task A
Task B
Task C
Task D
```

`hasNext()` returns `true` while an element remains; `next()` returns the next element and moves the cursor forward. **Always call `next()` only after confirming `hasNext()`** — otherwise `next()` throws `NoSuchElementException`:

```java
@Test
void whenNoNextElementAndCallNext_thenThrowNoSuchElementException() {
    Iterator<Task> iterator = tasks.iterator();
    for (int i = 1; i <= tasks.size(); i++) {
        iterator.next();
    }
    assertFalse(iterator.hasNext()); // no "next" element anymore
    assertThrows(NoSuchElementException.class, () -> iterator.next());
}
```

### 3.2. Safe Element Removal During Iteration

Where an enhanced for-each loop throws, an `Iterator` can safely remove via `remove()`:

```java
@Test
void whenRemovingTaskDuringIteration_thenCorrect() {
    Iterator<Task> iterator = tasks.iterator();
    Task removedTask = null;
    while (iterator.hasNext()) {
        Task task = iterator.next();
        if (task.getName().equals("Task C")) {
            removedTask = task;
            iterator.remove();
        }
    }
    assertEquals(3, tasks.size());
    assertEquals("Task C", removedTask.getName());
    assertFalse(tasks.contains(removedTask));
}
```

> `remove()` must be called after a `next()` and only once per `next()`; otherwise it throws `IllegalStateException`.

### 3.3. Using `forEachRemaining()`

Concisely iterates from the current cursor position to the end:

```java
@Test
void whenUsingForEachRemaining_thenIterateFromCurrentPosition() {
    Iterator<Task> iterator = tasks.iterator();
    // skip tasks before "Task B" (inclusive)
    while (iterator.hasNext()) {
        Task task = iterator.next();
        if (task.getName().equals("Task B")) {
            break;
        }
    }
    System.out.println("Tasks after [ Task B ]:");
    iterator.forEachRemaining(task -> {
        System.out.println(task.getName());
    });
}
```

Output:

```
Tasks after [ Task B ]:
Task C
Task D
```

The lambda is a **`Consumer`** defining the action for each remaining element. Notes: the action **should not modify the collection**, and since it uses the iterator's **same internal cursor**, it isn't suitable inside a manual iteration loop.

## 4. Meeting `ListIterator`

`ListIterator` is a more advanced version of `Iterator`, designed for lists. It **extends `Iterator`** and adds the ability to go **forward and backward** and to **insert or update** elements during iteration. It is **only available for collections that implement `List`**.

### 4.1. Backward Iteration

`hasPrevious()` and `previous()` traverse backward:

```java
@Test
void whenUsingListIterator_thenReverseTraversalCorrect() {
    ListIterator<Task> iterator = tasks.listIterator(tasks.size());
    while (iterator.hasPrevious()) {
        Task task = iterator.previous();
        System.out.println(task.getName());
    }
}
```

Output:

```
Task D
Task C
Task B
Task A
```

`listIterator(int)` takes a starting cursor position. From there you can move forward (`hasNext`/`next`) or backward (`hasPrevious`/`previous`). Passing `size()` positions the cursor just after the last element, enabling full reverse traversal. Note: `forEachRemaining()` always moves **forward** from the cursor regardless of prior direction.

### 4.2. Inserting New Elements During Iteration

`add()` inserts at the cursor during iteration:

```java
@Test
void whenUsingListIteratorAdd_ElementGetsInserted() {
    ListIterator<Task> iterator = tasks.listIterator();
    while (iterator.hasNext()) {
        Task task = iterator.next();
        if (task.getName().equals("Task C")) {
            iterator.add(new Task("042", "Magic Task", "This is a magic task!", null));
        }
    }
    assertEquals(5, tasks.size());
    assertEquals("Magic Task", tasks.get(3).getName());
    System.out.println("After calling add() in ListIterator's iterations:");
    for (Task task : tasks) {
        System.out.println(task.getName() + " - " + task.getDescription());
    }
}
```

Output:

```
After calling add() in ListIterator's iterations:
Task A - This is Task A
Task B - This is Task B
Task C - This is Task C
Magic Task - This is a magic task!
Task D - This is Task D
```

The new task is inserted **after** "Task C" (at the current cursor position).

### 4.3. Replacing Elements During Iteration

`set()` replaces the element last returned by `next()`/`previous()`:

```java
@Test
void whenUsingListIteratorSet_ElementIsUpdated() {
    ListIterator<Task> iterator = tasks.listIterator();
    while (iterator.hasNext()) {
        Task task = iterator.next();
        if (task.getName().equals("Task C")) {
            iterator.set(new Task("042", "Magic Task", "This is a magic task!", null));
        }
    }
    assertEquals(4, tasks.size());
    assertEquals("Magic Task", tasks.get(2).getName());
    System.out.println("After calling set() in ListIterator's iterations:");
    for (Task task : tasks) {
        System.out.println(task.getName() + " - " + task.getDescription());
    }
}
```

Output:

```
After calling set() in ListIterator's iterations:
Task A - This is Task A
Task B - This is Task B
Magic Task - This is a magic task!
Task D - This is Task D
```

"Task C" is replaced in place — size stays at 4 (unlike `add()`, which grows the list).

## 5. Using `Iterable.forEach()`

Implementing `Iterable` also enables the **`forEach()`** method: pass the per-element logic as a **`Consumer`** lambda for concise, expressive iteration.

### 5.1. Basic Iteration

```java
@Test
void whenUsingIterableForEach_ElementDataIsConsumed() {
    List<String> expectedCodes = List.of("001", "002", "003", "004");
    List<String> collectedCodes = new ArrayList<>();
    tasks.forEach(task -> collectedCodes.add(task.getCode()));
    assertNotNull(collectedCodes);
    assertEquals(4, collectedCodes.size(), "The collected list should have 4 codes");
    assertEquals(expectedCodes, collectedCodes, "The collected codes should match the expected codes");
}
```

### 5.2. Modifying Object State

`forEach()` returns `void`, but performing side effects (like updating fields) inside the lambda is acceptable when appropriate:

```java
@Test
void whenUsingIterableForEach_shouldSetDueDateForAllTasks() {
    LocalDate expectedDueDate = LocalDate.of(2050, 12, 31);
    tasks.forEach(task -> task.setDueDate(expectedDueDate));
    tasks.forEach(task -> {
        assertNotNull(task.getDueDate(), "Due date should not be null");
        assertEquals(expectedDueDate, task.getDueDate(), "Due date should match the expected date");
    });
}
```

> Modifying an element's **fields** is fine; **structurally modifying** the collection (add/remove) inside `forEach()` is not, and risks a `ConcurrentModificationException`.

## 6. Comparing Iteration Techniques

| Feature | `Iterator` | `ListIterator` | Enhanced for-each |
|---|---|---|---|
| Forward traversal | Yes | Yes | Yes |
| Reverse traversal | No | Yes | No |
| Remove during iteration | Yes | Yes | No |
| Insert/update during iteration | No | Yes | No |
| Bulk action with `forEachRemaining()` | Yes | Yes (inherited) | No |
| Works with all `Collection` types | Yes | No (only `List`) | Yes |
| Concise syntax | More verbose | More verbose | Yes |

**Guidance:**

- Use the **enhanced for-each** loop or **`Iterable.forEach()`** for simple read-only iteration, or for modifying object values.
- Use an **`Iterator`** when you need to **remove** elements during iteration.
- Use a **`ListIterator`** with a `List` when you need **bidirectional** traversal and **insert/update** as you go.

---

## 7. Conclusion

`Iterator` and `ListIterator` provide fine-grained control over traversal beyond enhanced for-each loops. Core `Iterator` methods handle forward iteration and safe removal; `ListIterator` adds bidirectional traversal, insertion, and replacement; and `Iterable.forEach()` offers a concise, lambda-based alternative for straightforward iteration. The right choice depends on whether you need simple read-only access, safe removal, or the full bidirectional-modification power of `ListIterator`.
